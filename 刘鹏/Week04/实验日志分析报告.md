## 4. 应该怎么调整

### 4.1 最重要：扩大数据量

当前 500 条、12 类，平均每类只有约 42 条，少数类只有 7 到 13 条。

推荐先用 2000 到 5000 条，保持 `stratify` 分层抽样：

```python
dataset_df = dataset_df.sample(frac=1, random_state=42).reset_index(drop=True)
dataset_df = dataset_df.iloc[:2000]   # 或 5000

labels = lbl.fit_transform(dataset_df[1].values)
texts = list(dataset_df[0].values)
```

为什么：

- BERT 需要足够样本才能学出稳定的类别边界。
- 当前 accuracy 平台期说明模型能力还没用完，是数据限制了它。
- 少数类样本太少，模型大概率直接忽略它们。

预期耗时（按当前 500 条 4.4 分钟估算）：

```text
2000 条约 18 分钟
5000 条约 44 分钟
```

### 4.2 修复 checkpoint 保存问题

当前配置：

```python
save_strategy="epoch",
save_total_limit=1,
load_best_model_at_end=True,
```

问题：`save_total_limit=1` 会删除旧 checkpoint，但 `load_best_model_at_end` 又要加载历史最优模型，可能出现“最优模型已经被删掉”的情况。

改为：

```python
save_total_limit=3,
metric_for_best_model="accuracy",
```

这样每个 epoch 的 checkpoint 都能保留，训练结束会真正加载准确率最高的那个。

### 4.3 先减到 3 个 epoch

当前 500 条、100 步、4 epoch，学习率到第 4 个 epoch 已经接近 0。

改为：

```python
num_train_epochs=3,
```

为什么：

- 第 4 个 epoch 的 learning_rate 是 2.22e-07，几乎没有学习能力。
- 3 epoch 就能省掉约 1 分钟无效训练。
- 如果扩到 2000 条以上，总步数变多，再回到 4 epoch 是合理的。

### 4.4 加梯度裁剪

当前 `grad_norm` 在 6.4 到 11.1，偏大。

改为：

```python
max_grad_norm=1.0,
```

为什么：

- 梯度范数过大说明某些步骤参数更新过猛，训练容易震荡。
- BERT 微调中限制梯度范数是常见做法，能提高稳定性。

### 4.5 max_length 改为 32

实际文本 P95 只有 22 个 token。

改为：

```python
max_length=32
```

为什么：

- 64 会填充大量无意义 padding，白耗 CPU 算力。
- 32 对当前数据基本无损，训练会更快。

## 6. 怎么验证调整是否真的有效

不要只看 accuracy 涨了 1 个点，建议按这个顺序看：

1. `eval_loss` 是否继续下降。
2. `eval_accuracy` 是否明显超过当前置信区间上界（约 0.90）。
3. 用 `classification_report` 看每个类别的 F1，尤其是 `TVProgram-Play`、`Other`、`Audio-Play`。
4. 用 `experiments.csv` 对比多轮实验。
5. 用 TensorBoard 看 loss、accuracy、learning_rate、grad_norm 曲线。

## 7. 结论

当前模型的训练是成功的：准确率从 0.59 提升到 0.82。

下一步不应继续盲目加 epoch 或微调学习率，而应该：

```text
先扩数据
-> 再修 checkpoint 保存
-> 最后固定参数做多轮对比
```
