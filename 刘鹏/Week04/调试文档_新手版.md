## 1. 调参前先把基线改“干净”

下面的改动不影响业务逻辑，但会让实验结果更可靠：

```python
training_args = TrainingArguments(
    output_dir='./results',
    num_train_epochs=3,
    per_device_train_batch_size=16,
    per_device_eval_batch_size=16,
    warmup_steps=10,
    learning_rate=2e-5,
    weight_decay=0.01,
    logging_dir='./logs',
    logging_steps=10,
    eval_strategy="epoch",
    save_strategy="epoch",
    load_best_model_at_end=True,
    metric_for_best_model="accuracy",
    save_total_limit=3,
    report_to=[],
)
```

每个改动的原因：

| 参数 | 为什么这样改 |
| --- | --- |
| `metric_for_best_model="accuracy"` | 让 `load_best_model_at_end` 真正按准确率选最优 checkpoint，而不是默认按 loss |
| `save_total_limit=3` | 只保留最近 3 个 checkpoint，避免磁盘被撑满 |
| `report_to=[]` | 不向 wandb 等平台上报日志，纯本地运行 |
| `logging_steps=10` | 25 步一个 epoch，10 步打一次日志，能看到训练 loss 变化 |
| `num_train_epochs=3` | 500 条小数据，3 epoch 是更合理的起点，先看趋势 |

跑一次完整训练，记录这张基线表：

| 实验 | learning_rate | epochs | batch | max_length | warmup | weight_decay | eval_accuracy | eval_loss | 耗时 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| baseline | 2e-5 | 3 | 16 | 64 | 10 | 0.01 | ? | ? | ? |

## 2. 实战调参：学习率优先

学习率是 BERT 微调中影响最大的超参数，第一个就测它。

固定其他参数，只改 `learning_rate`，做 3 组：

| 实验 | learning_rate | 其他参数 |
| --- | --- | --- |
| lr_1e5 | 1e-5 | 全部固定 |
| lr_2e5 | 2e-5 | 全部固定 |
| lr_5e5 | 5e-5 | 全部固定 |

改法：

```python
learning_rate=1e-5,   # 或 2e-5 / 5e-5
```

判断标准：

```text
eval_accuracy 更高 + eval_loss 更低 = 更好
```

同时看训练日志：

```text
loss 稳定下降                  = 正常
loss 忽大忽小 / grad_norm 很大  = 学习率可能太大
loss 几乎不动                  = 学习率可能太小
```

小数据量意图分类的常见规律：`2e-5` 稳定且效果不错；`1e-5` 可能略差但更稳；`5e-5` 偶尔会更快过拟合或波动更大。以你自己跑出来的 3 个数为准。

## 3. 实战调参：epochs + 早停

小数据上，epochs 太多是过拟合的第一来源。

做法：固定最优学习率，测 `epochs=2 / 3 / 5`。

判断方式看每轮评估：

```text
eval_accuracy 每轮都在涨      = 还能继续训练
eval_accuracy 开始下降        = 已经过头
eval_loss 回升 + acc 下降     = 过拟合信号，立刻停
```

更省事的做法是加早停回调：

```python
from transformers import EarlyStoppingCallback

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=train_dataset,
    eval_dataset=test_dataset,
    compute_metrics=compute_metrics,
    callbacks=[EarlyStoppingCallback(early_stopping_patience=1)],
)
```

`patience=1` 表示：连续 1 个 epoch 准确率没有进步就停止训练，并加载历史最优 checkpoint。

实战日志示例：

```text
epoch 1: eval_accuracy 0.72
epoch 2: eval_accuracy 0.82
epoch 3: eval_accuracy 0.84
epoch 4: eval_accuracy 0.83   # 开始下降
epoch 5: eval_accuracy 0.82   # 继续下降
```

结论：最优在第 3 个 epoch，`patience=1` 会在第 4 个 epoch 后停止，省掉后面无效训练。

## 4. 实战案例：准确率一直卡在 0.1 左右

### 现象

```text
epoch 1: eval_accuracy 0.11
epoch 2: eval_accuracy 0.12
epoch 3: eval_accuracy 0.11
```

### 排查顺序

1. 类别数对不对：确认打印 `类别数量：12`。
2. 数据有没有打乱：确认 `sample(frac=1, random_state=42)` 存在。
3. 学习率有没有真正生效：看日志里的 `learning_rate`，如果一直只有 `9.9e-06`，说明 warmup 太大，总步数还没过预热期。
4. `max_length` 是否太小：如果文本比 32 长很多，截断后信息丢失。

### 当前脚本的修复结果

你现在的配置已经规避了这个问题：

```python
warmup_steps=10,      # 总步数约 100，10 步预热是合理比例
learning_rate=2e-5,   # 显式设置，不再依赖默认值
```

## 5. 实战案例：过拟合

### 典型日志

```text
epoch 1: train_loss 1.90, eval_loss 1.80, eval_accuracy 0.60
epoch 2: train_loss 0.70, eval_loss 1.60, eval_accuracy 0.75
epoch 3: train_loss 0.30, eval_loss 1.40, eval_accuracy 0.80
epoch 4: train_loss 0.15, eval_loss 1.50, eval_accuracy 0.78
```

注意 epoch 4：训练 loss 还在降，但 eval_loss 回升、准确率下降。这就是典型的过拟合：模型把训练集背下来了，但测试集上变差。

### 处理优先级（从便宜到贵）

#### 1. 减少 epochs / 开早停

第 3 节已经给了代码，这是最优先的手段。

#### 2. 加大 weight_decay

```python
weight_decay=0.05,   # 或 0.1
```

`weight_decay` 是正则化强度，越大越不容易记住训练集细节。

#### 3. 降低学习率

```python
learning_rate=1e-5,
```

更小的步长配合早停，通常能得到更平滑的模型。

#### 4. 使用 label smoothing

```python
label_smoothing_factor=0.1,
```

它让模型不要太“自信”地贴近训练集，对防过拟合和类别不平衡都有帮助。

#### 5. 加大 BERT 的 dropout

在加载模型前修改 config：

```python
from transformers import BertConfig

config = BertConfig.from_pretrained(
    '../../models/google-bert/bert-base-chinese',
    num_labels=len(lbl.classes_),
)
config.hidden_dropout_prob = 0.3
config.attention_probs_dropout_prob = 0.2

model = BertForSequenceClassification.from_pretrained(
    '../../models/google-bert/bert-base-chinese',
    config=config,
)
```

dropout 是在训练时随机“关掉”一部分神经元，让模型不能依赖固定路径，是经典防过拟合手段。

#### 6. 用更多数据

当前只用了 500 条。如果过拟合严重，可以去掉 `[:500]`，改用更多数据：

```python
labels = lbl.fit_transform(dataset_df[1].values)
texts = list(dataset_df[0].values)
```

代价是训练时间变长，但泛化能力通常会明显更好。

### 怎么判断已经修好

```text
训练结束时：
eval_accuracy 不再下降
eval_loss 没有回升
train_loss 与 eval_loss 差距明显缩小
```

## 6. 实战评估：不要只看 accuracy

准确率在类别不平衡时会被“平均”掩盖问题。比如 12 类里某一类样本很少，模型全部不预测该类，准确率可能仍然很高。

训练结束后加一段分类报告：

```python
import numpy as np
from sklearn.metrics import classification_report, confusion_matrix

pred_result = trainer.predict(test_dataset)
y_pred = np.argmax(pred_result.predictions, axis=1)

print(classification_report(
    test_labels,
    y_pred,
    target_names=list(lbl.classes_),
    zero_division=0,
))
print(confusion_matrix(test_labels, y_pred))
```

三个指标用大白话理解：

| 指标 | 大白话 |
| --- | --- |
| precision | 模型预测成“某类”的样本里，有多少真属于该类 |
| recall | 真正属于“某类”的样本里，模型找回了多少 |
| f1-score | precision 和 recall 的平衡值 |

调优目标不是单看 accuracy，而是让每个类别的 F1 都不要太差，尤其是实际业务中最关心的类别。

## 8. 推荐的一轮完整实验流程

照这个顺序做，不盲目乱试：

1. 跑 baseline，记录 `eval_accuracy` / `eval_loss` / 耗时。
2. 学习率三组：`1e-5 / 2e-5 / 5e-5`，选最好的。
3. 用最好学习率测 epochs：`2 / 3 / 5`，必要时开早停。
4. 如果出现过拟合，依次试 `weight_decay=0.05`、`label_smoothing_factor=0.1`、加大 dropout。
5. 如果文本长度影响大，再测 `max_length=32 / 64 / 128`，同时记录耗时。
6. 选出最优配置，再跑一次，保存模型和类别列表。
7. 用第 6 节的分类报告确认每个类别的 F1。

实验记录模板：

| 实验 | lr | epochs | batch | max_len | warmup | wd | acc | eval_loss | 耗时 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| baseline | 2e-5 | 3 | 16 | 64 | 10 | 0.01 | ? | ? | ? | 基准 |
| lr_1e5 | 1e-5 | 3 | 16 | 64 | 10 | 0.01 | ? | ? | ? | |
| lr_5e5 | 5e-5 | 3 | 16 | 64 | 10 | 0.01 | ? | ? | ? | |
| ep5 | 2e-5 | 5 | 16 | 64 | 10 | 0.01 | ? | ? | ? | |
| wd05 | 2e-5 | 3 | 16 | 64 | 10 | 0.05 | ? | ? | ? | |

### 9.4 包装成 FastAPI 接口

新建 `app.py`：

```python
import json
import torch
from fastapi import FastAPI
from pydantic import BaseModel
from transformers import BertTokenizer, BertForSequenceClassification

labels = json.load(open("labels.json", encoding="utf-8"))
tokenizer = BertTokenizer.from_pretrained("../../models/google-bert/bert-base-chinese")
model = BertForSequenceClassification.from_pretrained("./bert_text_classifier")
model.eval()

app = FastAPI()


class RequestBody(BaseModel):
    text: str


@app.post("/predict")
def predict_endpoint(body: RequestBody):
    inputs = tokenizer(body.text, return_tensors="pt", truncation=True, padding=True, max_length=64)
    with torch.no_grad():
        logits = model(**inputs).logits
    label = labels[logits.argmax(dim=-1).item()]
    return {"text": body.text, "label": label}
```

安装依赖并启动：

```powershell
pip install fastapi uvicorn

```

调用：

```powershell
curl -X POST http://127.0.0.1:8000/predict -H "Content-Type: application/json" -d '{"text":"帮我查一下明天的天气"}'
```

## 10. 常见问题速查

| 现象 | 优先检查 | 解决办法 |
| --- | --- | --- |
| accuracy 卡在 0.1 | 类别数、数据顺序、warmup | 打乱数据，`learning_rate=2e-5`，`warmup_steps=10` |
| 训练 loss 降，eval 变差 | 过拟合 | 减 epochs、开早停、加 weight_decay / dropout |
| loss 为 NaN | 学习率过大 | 降到 1e-5 或 5e-6 |
| 显存不足 | batch 或 max_length 太大 | `batch_size=8`，`max_length=32` |
| 训练太慢 | CPU 训练 BERT | 先冒烟 `max_steps=2`，再缩小数据量 |
| checkpoint 把磁盘占满 | 保存太多 | 加 `save_total_limit=3` |
| 弹出 wandb 提示 | 默认开启上报 | 加 `report_to=[]` |

## 12. 日志去哪了？怎么转成表格

### 12.1 三种“日志”不要混淆

| 位置 | 里面是什么 | 什么时候会生成 |
| --- | --- | --- |
| 终端输出 | `loss`、`eval_accuracy` 等打印 | 每次运行都会出现，但不会自动存成文件 |
| `Week04\logs\` | TensorBoard 二进制事件文件 | 只有启用了 TensorBoard 写入才生成 |
| `Week04\results\checkpoint-*\trainer_state.json` | Trainer 自动保存的结构化日志 `log_history` | 每次保存 checkpoint 都会生成 |

你看到日志在 JSON 里，是因为：

1. `trainer_state.json` 是 Trainer 的设计：训练过程中把每一轮指标自动记录到 `log_history`，并随 checkpoint 保存，用于恢复训练和选取最优模型。
2. `logging_dir='./logs'` 只是 TensorBoard 专用目录。没有安装或启用 `tensorboard` 时，这个目录就是空的，这不影响训练。

### 12.2 为什么 `learning_rate` 一直在变

`learning_rate=2e-5` 是“最大学习率”，不是全程固定值。

训练时默认使用“预热 + 线性衰减”：

```text
前 10 步：从接近 0 逐渐升到 2e-5（预热）
后面：从 2e-5 逐渐衰减到接近 0
```

所以日志里的 `learning_rate` 每个 step 都不同，这是正常现象。

### 12.3 把 JSON 日志转成表格

在 `Week04` 目录下运行：

```powershell
python logs_to_table.py
```

脚本会自动在 `results` 里找最新的 `trainer_state.json`，生成：

```text
training_log_table.md
training_log_table.csv
```

也可以指定文件和生成 Excel：

```powershell
python logs_to_table.py --json results\checkpoint-75\trainer_state.json --excel
```

生成的表格包含 `step / epoch / type / loss / learning_rate / grad_norm / eval_loss / eval_accuracy` 等字段，训练行和评估行会分开标注。

## 13. 大厂怎么做实验追踪？不只是肉眼看日志

你说得对，大厂不会靠人肉盯日志。它们把“一次训练”当成一个完整的实验记录，通常分四层：

### 第 1 层：结构化日志

你已经有了：`trainer_state.json` 里的 `log_history` 就是结构化日志。它记录每一步的 loss、学习率、每轮评估指标，机器可读。

### 第 2 层：实验台账 CSV

当前脚本已经加上了自动记录功能。每次完整训练结束后，会自动追加一行到：

```text
Week04\experiments.csv
```

每一行包含：

```text
时间、learning_rate、epochs、batch_size、warmup_steps、weight_decay、
max_length、test_size、data_size、num_labels、
eval_accuracy、eval_loss、train_loss、train_runtime、best_metric、output_dir
```

这样你跑 10 次实验，就能看到 10 行对比，直接用 Excel 打开即可。

### 第 3 层：训练曲线可视化

肉眼看单次日志容易漏掉趋势，所以行业里用曲线图看：

- 训练 loss 曲线：是否稳定下降。
- 评估 loss / accuracy 曲线：是否过拟合。
- learning_rate 曲线：学习率调度是否正常。
- grad_norm 曲线：训练是否震荡。

工具推荐：

| 工具 | 用途 | 适合阶段 |
| --- | --- | --- |
| TensorBoard | 本地看曲线 | 刚入门 |
| MLflow | 本地实验追踪 + 模型注册 | 个人 / 小团队 |
| Weights & Biases | 云端对比实验 | 团队协作 |
| Neptune / Comet | 云端实验平台 | 中型团队 |
| SageMaker Experiments | AWS 生态 | 公司级 |

### 第 4 层：可复现实验体系

大厂评价一个实验，不只记录 accuracy，还会记录：

```text
超参数
随机种子
数据版本
代码版本 / git commit
运行环境 / 依赖版本
模型文件位置
评估指标
```

这样任何一个实验都能被完整复现，不会出现“当时明明跑出 0.9，现在跑不出来了”的情况。

## 14. TensorBoard 实战接入

TensorBoard 是最轻量的曲线可视化工具，适合本地单机看训练趋势。

### 14.1 安装

在 `py312` 环境中执行：

```powershell
pip install tensorboard
```

当前环境已经安装好 `tensorboard 2.21.0`。

### 14.2 让 Trainer 写入 TensorBoard

脚本里已经设置：

```python
logging_dir='./logs',
report_to=["tensorboard"],
```

这两个参数的意思是：

- `logging_dir='./logs'`：事件文件写到 `Week04\logs`。
- `report_to=["tensorboard"]`：启用 TensorBoard 回调。

训练结束后，`logs` 目录会出现 `events.out.tfevents.*` 文件。

### 14.3 启动 TensorBoard

在 `Week04` 目录下执行：

```powershell
tensorboard --logdir=logs --port=6006
```

如果 `tensorboard` 命令不在 PATH，用完整路径：

```powershell
D:\App_Library\Miniconda3\envs\py312\Scripts\tensorboard.exe --logdir=logs --port=6006
```

浏览器打开：

```text
http://localhost:6006
```

### 14.4 你能看到什么

进入 TensorBoard 的 SCALARS 页面，可以看到：

- `train/loss`：训练损失曲线。
- `train/learning_rate`：学习率曲线，能看到预热和衰减。
- `train/grad_norm`：梯度大小，观察训练是否震荡。
- `eval/loss`：评估损失。
- `eval/accuracy`：评估准确率。

曲线比数字更直观：例如评估准确率曲线到了某个 epoch 开始往下走，就是过拟合信号。

### 14.5 常见问题

| 问题 | 解决 |
| --- | --- |
| `logs` 目录没有事件文件 | 确认 `report_to=["tensorboard"]`，且训练至少跑过 logging 步 |
| 端口被占用 | 换端口：`--port=6007` |
| 曲线没更新 | 刷新页面；训练正在跑时可以实时看 |

## 15. MLflow 对笔记本电脑的要求

MLflow 可以完全在本地运行，不强制联网，也不要求 GPU。

### 15.1 安装

```powershell
pip install mlflow
```

当前环境已经安装好 `mlflow 3.15.1`。

### 15.2 硬件要求

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| GPU | 不需要 | MLflow 只负责记录，训练仍然由 PyTorch 跑 |
| 内存 | 建议 8GB 以上 | 4GB 能跑但会比较紧张 |
| 磁盘 | 建议留 2-3GB | 每个 checkpoint 约 400MB，`mlruns` 会保存 artifact |
| 浏览器 | 需要 | `mlflow ui` 启动后要用浏览器打开 |
| Python | py312 可以 | 已安装成功 |

### 15.3 本地使用方式

```python
mlflow.set_tracking_uri("file:./mlruns")
```

所有实验数据保存在本地 `mlruns` 目录，不需要注册云账号。

### 15.4 什么时候用

- 实验少于 5 次：用 `experiments.csv` 足够。
- 实验超过 5 次，需要批量对比参数和指标：上 MLflow。
- 需要团队共享实验结果：再考虑云端版 W&B 或公司内部平台。
